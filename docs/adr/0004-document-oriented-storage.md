# ADR 0004 永続化は文書指向にする

状態: 採用
決定日: 2026-11-27

## 文脈

v0.2 までは Room（正規化）を前提にしていた。DataStore も設定用として併記していた。

## 決定

本体データは JSON 1件1ファイル＋インメモリ索引で持つ。設定は Jetpack DataStore（Preferences）に置く。DataStore を本体データの器には使わない。

## 理由

- **構造**: データは run を単位とする木（run → idol 1 / support 6 / memory 4 / item 7 / skill 33）。1件を丸ごと読んで丸ごと書く。集約をまたぐトランザクションが要らない
- **クエリ**: すべて「全件読んで集計」の形。ペア共起も型分類も差分も SQL のインデックスが効かない。pHash の近傍探索には SQLite に索引がない
- **件数**: 1000 run × 2KB ≈ 2MB、カード辞書 2000 種 × 0.5KB ≈ 1MB。全部メモリに載る
- カード辞書は後から育つので、外部キー制約が邪魔になる（未詳を許す必要がある）。開発中のスキーマ変更も、未知フィールドを捨てて読める JSON の方が軽い

DataStore は設定向けの API で、書き込みのたびに全体をシリアライズし、部分読み出しができない。レコードの器ではない。

## 帰結

- SQL の GROUP BY を失う。集計は Kotlin の純関数になる（テストは書きやすくなる）
- FTS を失う。カード 2000 種の線形走査は数 ms なので、必要になってから考える
- 参照整合性は読み込み時に検証し、欠けた `card_id` は「未詳」として扱う
- 書き込みは temp に書いて rename。読み込みは起動時に索引だけ、集計を開いたときに全件
- Room と KSP を依存から外せる（ビルドが速くなり APK も少し小さい）
- **戻す基準**: 1シーズンあたりの run が数千を超える、または効果文の検索が実用速度を割る。そのときはカード辞書だけ SQLite FTS に部分移行する

## 置換

v0.2 時点の「DB は Room」という前提を置換する。
