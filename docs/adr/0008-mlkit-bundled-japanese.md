# 0008 OCR は ML Kit の日本語 bundled を使う

- 状態: 採用
- 日付: 2026-11-27
- 置換: なし

## 文脈

端末完結（`INTERNET` を宣言しない）が設計の制約（§1）。OCR はこの制約と衝突しやすい。ML Kit には配布形態が2つある。

- **unbundled**: Play Services 経由。端末に日本語モデルが無ければダウンロードが走る
- **bundled**: モデルを APK に同梱。オフラインで完結する

代替は Tesseract と PaddleOCR。Tesseract は日本語の縦書き・装飾文字に弱い。PaddleOCR はネイティブ資産が大きく、依存の管理も重い。

## 決定

`com.google.mlkit:text-recognition-japanese` の **bundled** を使い、モデルを APK に含める。ML Kit への依存は `:app` に閉じ、`:core` には `TextRecognizer` インターフェースだけを置く（ADR 0007）。

## 理由

- unbundled は初回に通信しうる。宣言していない権限で動く経路を残すと、「通信しない」という約束が証明できなくなる
- bundled は端末の状態に依存せず、同じ入力に同じ結果を返す。抽出の再現性はこの題材の前提
- 日本語スクリプトに公式対応しているのは ML Kit だけ

## 影響

- APK が数MB増える（arm64 単独、スクリプト1つ分）
- 初回の初期化にコストがある。OCR は取り込み時だけ呼び、常駐させない
- **OCR は JVM で動かない。** 認識の正しさは実機の固定画像で確かめる。判定・パース・集計は `:core` の単体テストで担保し、OCR の誤差は「不明」として吸収する設計にする（§7）
- `bundled` でも通信が発生する兆候が出たら、この決定を見直す

## 戻す基準

日本語の認識精度が実用に届かない、または bundled でも通信が観測されたとき。そのときは PaddleOCR の日本語モデルを試す。Tesseract は精度の観点で第一候補にしない。
